# M4 Run Loop, Economy & Shop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A pure, headless run layer (`@checkbreaker/run`) that plays a whole Checkbreaker run from a seed — stages, interest, chooser, shop, merge/sell/cut/repair, save/resume — plus the engine rule changes it needs and a bot that drives full runs.

**Architecture:** The engine gains interest in `Award`, single-use skills and a shared rarity roll. A new package `packages/run` holds a serializable `RunSession` and pure actions over it; it imports `engine` at runtime and only types from `content`, and never imports `gen`: it emits a `GenRequest` and is handed the stage (`provideStage`). `gen` returns the solver's solution beside the stage; `scripts/run-bot.ts` wires `gen` and `run` together and plays runs.

**Tech Stack:** TypeScript (strict, `noUncheckedIndexedAccess`), npm workspaces, Vitest 5, tsx, `yaml` (content only).

**Spec:** [docs/superpowers/specs/2026-11-13-m4-run-loop-design.md](../specs/2026-11-13-m4-run-loop-design.md) (U1–U15). Rule docs already updated: docs/02, 03, 05, 06, 07, 08, 09, 10.

## Global Constraints

- Engine and run are pure: no I/O, no `Math.random`, `Date.now` or `performance.now`; same inputs → deep-equal outputs; typed `Result` errors, never a throw on player-shaped input.
- `packages/engine` and `packages/run` have **zero runtime dependencies** (`"dependencies": {}` for engine; run may list only `@checkbreaker/engine`).
- `packages/run` never imports `@checkbreaker/gen`, and imports `@checkbreaker/content` only with `import type`.
- Every tuning number is read from `data/economy.yaml` / `content/examples/*.yaml` through `content` loaders; none is hard-coded.
- Every new data rule has a validator check in `scripts/validate-content.mjs` proven to fail on broken data.
- Interest: `min(5, floor(walletAtMate / 5) × 1)`; wallet read at R3 of the mating turn, before the award (U3, U4).
- Shop: skill chance 0.2 per slot 3–4; piece weights knight 35 · bishop 35 · rook 20 · queen 10; slot 1 knight/bishop/rook; repair 4, repeatable; reroll 2 after 1 free, max 3 per visit, redraws slots 1–4 (U2, U5, U12).
- Skills: single use, consumed on commit, duplicates in separate slots, loadout ≤ 3, prices Lockdown/Gallop/Bulwark 3 · Twin Step/Ascension/Recall 4 · Phase Step 5 (U6–U10).
- Sale: `min(floor(0.5 × price(type, rarity, act)), pricePaid ?? ∞)`, never the King or `spent` (U15).
- Shop act (prices, rarity pool, merge ceiling, sell price) = act of the stage just cleared.
- Commits: one per task, message prefix as shown, ending with the attribution line `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never stage `deepseek-subagent/` or `.superpowers/`.

## Review Focus

1. **Reload during stage I-3's Deployment** must not grant the free Twin Step twice — the grant happens once, on entering Deployment, and a loaded session never re-grants (test in Task 8).
2. **Leaving the shop before generation finishes** puts the session in `awaiting_stage`; `provideStage` with a stage whose seed is not the request's is refused with `stage_mismatch`, and a second `provideStage` after the stage is set is refused too (Task 8).
3. **Repair on a Legendary queen at full durability (1/1) or on a `spent` piece** is refused (`not_damaged` / `cannot_repair`), never charges coins (Task 6).
4. **The chooser closes exactly when the deck fits**: once the non-king deck is ≤ 8 the phase moves on by itself, so a ninth action cannot over-cut; a promotion that overflows by 2 needs two removals (Task 8).
5. **Recovery purchase records the discounted `pricePaid`**, so selling it later in any act never exceeds what was paid (Task 7 property test).
