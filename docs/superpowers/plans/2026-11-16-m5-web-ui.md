# M5 Web UI Vertical Slice Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `apps/web`, a React app in which one complete Checkbreaker run is playable from the title screen to the run Results, built on the pure run layer with no rules logic in the UI.

**Architecture:** `content` gains Node-free parsers fed with YAML text (the browser and the Node loaders share them). `engine` gains read-only view helpers (`engine/src/view.ts`) so the UI never computes a rule. `run` gains `restartStage`, `devSkipStage` and the M4 hygiene fixes. `apps/web` (Vite + React 18 + `useReducer`) holds one `RunSession`, calls `@checkbreaker/run` for every action, autosaves through a `localStorage` `RunStorage`, and gets stages from a generation Web Worker behind a `StageSource` interface.

**Tech Stack:** TypeScript (strict, `noUncheckedIndexedAccess`), npm workspaces, Vite 8.3.6 (already in the tree via vitest), React 18.3.1 + react-dom 18.3.1, `@vitejs/plugin-react` (a version whose peer range includes Vite 8), Vitest 5.0.5, `@testing-library/react` + `@testing-library/user-event`, jsdom, `yaml`.

**Spec:** [docs/superpowers/specs/2026-11-16-m5-web-ui-design.md](../specs/2026-11-16-m5-web-ui-design.md) (U1–U10). Rule docs already updated: docs/08, 09, 10, 11.

## Global Constraints

- **No rules logic in `apps/web`.** Legality, threats, costs, payouts, stalemate, deployment validity and par/overtime numbers come from `engine` or `run`. A number the UI computes itself is a bug.
- Main-thread files in `apps/web` import only: `@checkbreaker/engine` (never `/internal`), `@checkbreaker/run`, `@checkbreaker/content/parse`, `react`, `react-dom`, and the app's own files. Only `apps/web/src/state/generation.worker.ts` may also import `@checkbreaker/gen`. Only `apps/web/src/screens/Bench.tsx` may also import `packages/engine/test/bench-positions.ts`.
- Engine and run stay pure: no I/O, no `Math.random`, `Date.now` or `performance.now`; typed `Result` errors, never a throw on player-shaped input. `packages/engine` keeps `"dependencies": {}`; `packages/run` depends on `@checkbreaker/engine` only.
- No new tuning number: nothing is hard-coded that `data/economy.yaml` or `content/examples/*.yaml` holds.
- Dev skip pays the stage's pending base reward only (`pendingBase`), no par bonus, no interest, no further salvage; it sets `session.debug = true` for good; it shows only with the dev toggle on.
- Restart: Action phase and `stage.turnsUsed === 0` only; durability paid at START is never refunded; a piece START took to 0 stays `spent`.
- `SAVE_VERSION` stays `1`. Storage key `checkbreaker.save.1`. Dev toggle key `checkbreaker.dev` (per-browser convenience, off by default).
- Shortcuts: `Space` COMMIT, `Z` undo last queue entry, `ArrowLeft`/`ArrowRight` step through the preview, `C` Codex, `D` Deck, `Escape` close an overlay or cancel a selection.
- Planning arrows: right-drag draws, right-click marks, Shift/Ctrl/Alt pick colours 2/3/4 (none = 1), the same arrow or mark again removes it, a left click on the board or a COMMIT clears all; never saved; dashed, own palette, drawn under the ghost preview.
- `npm test` never runs the solver: web tests get stages from a `StageSource` double.
- Branch `M5` off `main` before the first change. Commit only when the user asks; when they do, one commit per task with the message shown, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never stage `deepseek-subagent/` or `.superpowers/`.

## Review Focus

1. **Reload after a restart, in Deployment:** the reloaded session still has `entryStage`, the deck shows the already-paid durability, and a second START pays again — never twice for one START, never zero (Task 3 test).
2. **A stale worker answer** (the player abandoned and started a new run while a stage was generating) is dropped by request id and never reaches `provideStage`; the player never sees `stage_mismatch` (Task 8 test).
3. **`localStorage` throws** (private mode, quota, blocked site data): the app still plays; the adapter reports the failure once as a banner and keeps the session in memory (Task 7 test).
4. **Buying a skill with a full loadout:** the UI asks which slot to replace; cancelling buys nothing and spends no coins (Task 12 test).
5. **Reload while `awaiting_stage`** (left the shop before generation finished): on launch the app re-posts the stored request and enters Deployment when it arrives (Task 8 test).
