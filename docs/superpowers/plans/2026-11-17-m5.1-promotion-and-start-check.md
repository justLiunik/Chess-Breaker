# M5.1 Chess Promotion and No Check at START Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the approved M5.1 rules:
- a spawned pawn on rank 8 becomes a piece the player chooses, stays on the board and joins the deck;
- the shop blocks the next stage while the deck is over 8;
- START may not give check;
- at most one queen is summoned per stage.

**Architecture:** The rules live in `packages/engine`:
- internal move generation, legality and queue resolution;
- `startStage` and the `deploymentStatus` / `promotionChoices` view helpers.

`packages/gen` follows them: no promotion roll, the `no_start_check` precondition, a solver that branches on promotion choices and respects the queen limit. `packages/run` drops the chooser phase and gates `leave`. `apps/web` asks the engine for promotion choices and shows the new refusals. The UI computes no rule.

**Tech Stack:** TypeScript 5, npm workspaces, Vitest 5 (node + jsdom projects), React 18, Vite 8.

**Spec:** `docs/superpowers/specs/2026-11-17-promotion-and-start-check-design.md`. Its decisions are P1–P10. The rules docs are already updated: docs/02 §2.2, §4, §5 and §9 (I9, I15, I16); docs/04; docs/06; docs/07; docs/08; docs/09.

## Global Constraints

- Promotion types: `type PromotionType = 'knight' | 'bishop' | 'rook' | 'queen'` (exported from `@checkbreaker/engine`). The promoted piece keeps the pawn's `rarity`. Enemy pawns still promote to a Normal queen.
- `Action` MOVE: `{ type: 'MOVE'; from: Square; to: Square; promotion?: PromotionType }`.
- New `MoveRejection` reasons: `'promotion_required'` (a spawned pawn reaches rank 8 without `promotion`) and `'promotion_not_allowed'` (`promotion` on a move that does not promote).
- New `invalid_deployment` reasons: `'gives_check'` (`to` = the checking piece's square) and `'queen_limit'` (`to` = the second queen's square). `DropRefusal` gains both. The tray reason gains `'queen_limit'`.
- New invariant I16: at Start, the black king is not in check.
- Queen limit: `EngineConfig.deployment.maxQueenSummons`, parsed from `deployment.maxQueenSummons` in `data/economy.yaml` (value 1). It counts summoned queens of any rarity. A queen from promotion does not count in its stage.
- Promoted deck instance:
  - `origin: 'promotion'`, `pricePaid: 0`, full `durabilityMax` for type × rarity, `status: 'in_deck'`;
  - `instanceId` keeps the existing `'p_' + hash(stageSeed, turnsUsed, atStep, square)` form;
  - the board piece carries that `instanceId` and has no `spawned` flag.
- Event: `{ type: 'pawn_promoted'; square: Square; pieceType: PromotionType; rarity: Rarity; instanceId: string }`.
- `BoardPiece.promotesTo` is removed everywhere (types, gen, fixtures, UI).
- Run layer:
  - `RunPhase` loses `'chooser'`; `RunSession` loses `chooser`; the `chooser_opened` event is gone;
  - a won stage goes straight to the shop (or the run end);
  - `leave` refuses `{ kind: 'deck_over_capacity'; size: number; capacity: number }` while the non-king deck count exceeds `c.deck.capacity`;
  - merge, sell and cut work in the shop only.
- Save: `SAVE_VERSION = 2`. The web storage key stays `checkbreaker.save.1`. A version 1 save is refused with the existing `unknown_version` message, with no migration. `loadSave` accepts an over-capacity deck in the `action`, `shop` and `ended` phases.
- No rules logic in `apps/web`: the promotion picker shows exactly `promotionChoices(...)`, and the shop gate comes from a dry run of `leave`. The import allowlist test must keep passing.
- Docs in English. Never stage `deepseek-subagent/` or `.superpowers/`. One commit per task on branch `M5.1`, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. No push, no merge.
- Determinism (I11): the generated-stage golden and determinism fixtures change because the promotion roll's RNG draw is gone. Re-record them with the repo's recording commands; never hand-edit them.

## Review Focus

1. **A promotion that captures on rank 8 and mates in the same step.** The new piece gives check as its type at once, and the win is recognised. I10 holds for that queue.
2. **A promoted piece captured by the enemy reply in the same COMMIT.** It is lost from the deck and counts in `piecesLost` (recovery offer).
3. **Two promotions in one queue**, for example a Legendary knight bonus move or skill credits. They give two distinct `instanceId`s and two deck instances.
4. **Deck at 9 in the shop:**
   - selling the promoted piece pays 0;
   - `leave` is refused at 9 and allowed at 8;
   - a reload while in the shop with 9 pieces is still gated.
5. **Queen limit across rarities:** a Normal queen and a Unique queen together are refused (`queen_limit`), and `deploymentStatus` shows the second one as unavailable after the first is placed.
