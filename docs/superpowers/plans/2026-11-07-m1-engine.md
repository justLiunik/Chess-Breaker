# M1 — Chess Core & Turn Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `packages/engine` — a pure, deterministic, dependency-free TypeScript engine for the
Action phase of a stage (moves, deferred-validation queue, R1–R5, stage end, enemy AI) — plus a
`packages/content` config loader and a terminal playground.

**Architecture:** Public state is the immutable `StageState`/`RunState` of the schemas. Move
generation works on an internal `Int8Array(64)` board shared by the queue (via conversion) and the
enemy search (mutated with make/unmake). Every public function takes an `EngineConfig` built from
`data/economy.yaml` by `packages/content`.

**Tech Stack:** TypeScript 5.9.3 (strict), Vitest 5.0.5, tsx 4.23.15, npm workspaces, Node ≥ 20,
`yaml` (content only), `chess.js` 1.4.0 (perft test only).

**Spec:** [docs/superpowers/specs/2026-11-07-m1-engine-design.md](../specs/2026-11-07-m1-engine-design.md)
— read it first. Rules authority: [docs/02](../../02-rules-framework.md).

## Global Constraints

- `packages/engine/package.json` has `"dependencies": {}`; nothing in `packages/engine/src` imports
  anything outside `packages/engine/src`.
- No `Math.random`, `Date.now`, `performance.now` or I/O in `packages/engine/src`.
- Public functions never mutate their inputs and never throw for inputs that match the types.
- Every tuning number comes from `EngineConfig`; no number from `economy.yaml` is written in engine code.
- Squares are algebraic strings `'a1'`…`'h8'`; internal index = `file + 8 × rank` (a1 = 0, h8 = 63).
- The player is White and moves up the board; the enemy is Black.
- No castling, no en passant; the king is never captured (no move to a king's square is generated).
- Exact devDependency versions at the root: `typescript@5.9.3`, `vitest@5.0.5`, `tsx@4.23.15`,
  `chess.js@1.4.0`. `packages/content` depends on `yaml@^2.6.1` (already in the root).
- Commits: one per task, message in the imperative, ending with
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

- A queue whose first move gives check and whose second removes it (when credits allow) must be
  accepted — deferred validation must not be "fixed" mid-queue. Pinned in Task 6.
- A move onto the enemy king's square is refused with `king_square`, even though the square is
  "occupied by an enemy". Pinned in Task 4.
- A player capture that leaves the enemy only a boxed-in king ends the stage as a **loss**
  (`enemy_stalemated`), not a pass. Pinned in Task 7.
- Calling `enemyMove` twice on the same input, with an unrelated call in between, returns the same
  move (no hidden state across calls). Pinned in Task 10.
- A player pawn moving to rank 8 vanishes from the board and the event carries its `promotesTo`;
  nothing appears on its square. Pinned in Task 6.

### Task 9: Search

**Files:**
- Create: `packages/engine/src/enemy/search.ts`
- Test: `packages/engine/test/enemy-search.test.ts`

**Interfaces:**
- Consumes: Task 8, `legalMoves`, `makeMove`, `unmakeMove`, `inCheck`.
- Produces: `scoreRootMoves(b: Int8Array, playerTurnsLeft: number, depth: number, config: EngineConfig): { move: Move; score: number }[]`
  — Black to move at the root; returns **every** root move in the stable order (captures by most
  valuable victim / least valuable attacker, then checks, then `from` index, then `to` index), with
  exact scores for every move tying the best and upper bounds below it.

Rules the implementation must follow (spec §7):
- Black maximises, White minimises; one ply = one move; `ply` counts from the root.
- Black to move: no legal move → in check: `enemyMated + ply`; else `playerMated − ply`
  (stalemate is the player's loss). Otherwise, if `playerTurnsLeft === 0` → `playerOutOfTurns`.
- White to move: `playerTurnsLeft === 0` → `playerOutOfTurns`; else no legal move →
  `playerMated − ply` (mate or stalemate alike). After each White move `playerTurnsLeft − 1`.
- Terminal checks run at every node **before** the depth test, so a mate or stalemate on the
  horizon is scored as a terminal, never handed to quiescence.
- Depth 0 → quiescence: stand pat on `evaluate`, captures only, both sides, at most
  `quiescenceMaxDepth` plies.
- Iterative deepening 1..`depth`; the best move of each iteration is tried first in the next.
- TT (`Map<number, Entry>`, new per `scoreRootMoves` call; skipped when
  `config.enemyAI.search.transpositionTable` is false): entry `{ depth, score, bound: 'exact' | 'lower' | 'upper', best }`;
  scores with `|s| ≥ 90000` are stored node-relative (`+ply` for positive, `−ply` for negative) and
  re-based on read.
- Root: the first move with a full window, every later move with `(best − 1, +∞)`.

  - Mate in 1: White `Ka1`, `Pa2`, `Pb2`; Black `Kh8`, `Re8`; depth 2 → `e8→e1` scores `99999`
    and no move scores higher.
  - Forced loss is scored by its distance: White `Kb6`, `Qc6`; Black `Ka8` (in check, only `Kb8`);
    depth 2 → the single move scores `−100000 + 2`.
  - Player stalemate counts as the player's loss: White `Ka1`; Black `Kc2`, `Qd3`; depth 2 →
    `d3→b3` (stalemate) and `d3→b1` (mate) both score `99999`.
  - Quiescence: White `Ka1`, `Rd1`, `Pd4`; Black `Kh8`, `Qd5`; depth 1 → `d5→d4` scores below the
    best non-capturing move.
  - Out of turns: any `MIDGAME_FENS` position with `playerTurnsLeft 0` at depth 2 → every move scores
    `50000` unless it mates.
  - TT on vs off: identical scores for the tied-best moves on all `MIDGAME_FENS` at depth 3.
